## Anti-drift principles

YAGNI — Build only what a current approved requirement asks for; no speculative features.
KISS — Use the simplest structure that satisfies the requirement.
DRY — Call existing logic rather than rewriting it.
SRP — Give each unit one coherent responsibility.
LA — Behavior must match an obvious reading of the requirement.
NAA — Declare authority-bearing abstractions in approved upstream authority or
amend it before use; do not silently expand behavior, shared contracts, data,
architecture or security boundaries. Proportionate private implementation/test
details remain permitted within the authorized scope.
